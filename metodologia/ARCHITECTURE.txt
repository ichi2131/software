                    FLUJO DE UNA SOLICITUD TÍPICA

═══════════════════════════════════════════════════════════════════════════════

Usuario hace login en login.html
                ↓
JavaScript ejecuta handleLogin(username, password)
                ↓
api-client.js → fetch POST /api/login
                ↓
Flask recibe la solicitud en api.py
                ↓
api.py llama a database.login(username, password)
                ↓
database.py ejecuta: SELECT * FROM users WHERE username=? AND password=?
                ↓
SQLite retorna los datos del usuario (si existen)
                ↓
database.login() retorna usuario o None
                ↓
api.py crea sesión y retorna JSON: {success: true, user: {...}}
                ↓
api-client.js recibe respuesta y guarda usuario en localStorage
                ↓
Frontend redirige a index.html
                ↓
✅ Usuario autenticado y navegando

                    COMPARACIÓN: ANTES vs DESPUÉS

═══════════════════════════════════════════════════════════════════════════════

ANTES (localStorage):
┌────────────────────────────────────────────────────────┐
│  Datos guardados en:                                   │
│  → localStorage del navegador                          │
│                                                        │
│  Problemas:                                            │
│  ❌ No persistente (se pierde si limpias cache)        │
│  ❌ No seguro (visible en JavaScript)                  │
│  ❌ No compartido entre dispositivos                   │
│  ❌ Sin auditoría                                      │
│  ❌ Sin control de acceso en servidor                  │
│  ❌ Pérdida total si elige "borrar datos"              │
└────────────────────────────────────────────────────────┘

DESPUÉS (Base de Datos):
┌────────────────────────────────────────────────────────┐
│  Datos guardados en:                                   │
│  → Archivo SQLite en el servidor                       │
│                                                        │
│  Ventajas:                                             │
│  ✅ Datos persistentes                                 │
│  ✅ Seguro (validación en servidor)                    │
│  ✅ Compartido entre dispositivos                      │
│  ✅ Auditoría completa (activity_log)                  │
│  ✅ Control de acceso por rol                          │
│  ✅ Backup y recuperación posible                      │
│  ✅ Escalable (fácil agregar usuarios)                 │
└────────────────────────────────────────────────────────┘

                    TECNOLOGÍAS UTILIZADAS

═══════════════════════════════════════════════════════════════════════════════

Frontend:
  - HTML5                    (Estructura)
  - CSS3                     (Estilos y animaciones)
  - JavaScript (ES6+)        (Lógica del cliente)
  - Fetch API                (Comunicación con API)

Backend:
  - Python 3.7+             (Lenguaje)
  - Flask 3.0.0             (Framework web)
  - Flask-CORS 4.0.0        (Comunicación entre dominios)
  - Werkzeug 3.0.1          (WSGI utilities)

Base de Datos:
  - SQLite 3                (Motor de BD)
  - Python sqlite3          (Driver)

Otros:
  - HTTP/REST               (Protocolo de comunicación)
  - JSON                    (Formato de datos)
  - Sessions/Cookies        (Autenticación)
